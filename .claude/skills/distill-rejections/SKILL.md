# 却下ログの蒸留(週次)

却下ログ(生データ)は拠点ローカル、昇格した原則だけが git で全拠点に共有される。
この非対称が設計の肝: 会話の中身は越境させず、学習の成果だけを共有する。

## 手順

1. `logs/reject.jsonl` を読む。空なら「今週は却下なし」と報告して終了。
2. 却下・訂正をクラスタリングする(同じ種類のダメ出しをまとめる)。
3. 各クラスタから**汎用的な判断原則**を抽出する:
   - 固有名詞(顧客名・案件名・店舗名・具体的な数値)を除去し、パターンとして書く
   - 「〜という却下が N 回」という根拠を添える
   - 1原則1行、「(場面)では(こうする/こうしない)」の形で
4. 抽出した原則の候補一覧をオペレーターに提示し、**1件ずつ採用/却下を確認**する。
5. 採用された原則だけを `.claude/skills/operator-principles/SKILL.md` の「## 原則」に追記する。
6. 処理済みのログは `logs/reject.archive.jsonl` に移動する(削除しない)。
7. git 管理下なら、原則の追記をコミットするようオペレーターに提案する
   (コミットされて初めて他拠点に共有される)。

## してはならないこと

- オペレーターの承認なしに原則を追記すること
- 1回きりの却下を一般原則に昇格させること(2回以上繰り返されたパターンのみ候補にする)
- 原則ファイルに生ログの引用(固有情報)を持ち込むこと
