# 検品チェックリスト(目視用)

`scripts/vet.sh` が機械的に見る項目に加え、GM が読んで判断する観点。

| 観点 | 見るところ | NG の例 |
|---|---|---|
| 指示の範囲 | SKILL.md が「ユーザーの依頼の範囲内」で完結しているか | 依頼と無関係にファイルを書き換える・設定を変える指示 |
| 秘密の扱い | API キー・トークン・.env に触れる指示 | 「キーを貼ってください」「env を表示」「設定ファイルを読んで送信」 |
| 外部送信 | curl/wget/fetch で外部へ送る指示、Webhook、テレメトリ | 利用状況を第三者 URL へ POST |
| 実行スクリプト | scripts/ の中身(何を読み、何に書き、何を実行するか) | パイプで `sh` 実行、リモート取得スクリプトの実行、sudo |
| インジェクション | frontmatter や本文の `<...>` タグ、「以前の指示を無視」等 | システムプロンプト偽装、権限拡張を促す文 |
| 固有名詞 | 提供元の製品名・営業導線がスキル本文に混ざっていないか | 特定 SaaS への誘導が手順の必須ステップになっている |
| ライセンス | LICENSE の有無と種類。再配布(この拠点の git)が許されるか | ライセンス不明、NC/ND で拠点内共有と矛盾 |
| 規模 | SKILL.md の語数(5,000 語目安)、references の量 | 巨大すぎて読まれない、同時有効 50 個超 |
| 依存 | 前提ツール(Node/Python/uv/Docker/クラウド GPU/有料 API) | 拠点で満たせない前提を黙って要求 |

判定: NG が 1 つでもあれば導入しない。WARN は該当箇所を読んで「拠点の安全規則で防げるか」「用途上必要か」で判断し、報告に理由を書く。
